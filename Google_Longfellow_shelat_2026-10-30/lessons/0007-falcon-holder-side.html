Falcon 验签拆解：为什么藏公钥几乎免费

这一课的收获：被问到 Falcon 时能用 60 秒讲清 Falcon 验签的四步（每步的输入和输出），算出「藏公钥时 Falcon ≈ 9 次 Keccak、ML-DSA ≈ 116 次」，并说清楚这个估算的边界。这是方向 F（「发证方改用 Falcon 签名，Longfellow 里新写 Falcon 验签电路」）的技术底气。

怎么读这一课：每个组件先给一张「黑盒卡片」（输入、输出、负责什么），折叠的「细节（可跳过）」讲内部怎么算，面谈不需要。ZK 的基本名词（statement 公开陈述、witness 秘密证据、prover、verifier）见第 0001 课第 0 节。

1. 故事线（slide 第 6 页）

Longfellow 今天证明的是「我持有一张 ECDSA 签名的证件」。要后量子，只需把发证方的签名算法换成 ML-DSA（Module-Lattice-Based Digital Signature Algorithm，NIST 后量子签名标准 FIPS 204）或 Falcon（Fast-Fourier Lattice-based Compact Signatures over NTRU，另一种格签名），holder（持有人）侧的电路改成验证新签名。发证方是单机签还是门限签，对持有人侧没有区别，所以这里不提 SHIELD / FLOCK。

  • B（ML-DSA 放进完整 mdoc 陈述）：验签电路已经有了（858 ms），下一步是和 MSO 哈希、属性、device binding 拼起来测端到端。门槛最低，先讲。
  • F（Falcon 电路）：Longfellow 现在没有 Falcon 电路。研究味更重，卖点见第 3 节。
  • A（藏公钥的 ML-DSA）：备用。他们说「PQ（Post-Quantum，后量子）只做 ML-DSA」时拿出来。

2. Falcon 验签的四步

整体
Falcon Verify（round-3 规范 v1.2，Alg. 16 = Algorithm 16）
输入
公钥 pk = 多项式 h；消息 m；签名 = (盐 r, 压缩后的 s)
输出
接受 / 拒绝
一句话
把消息哈希成一个多项式 c，用签名和公钥算出 (s₁, s₂)，检查它们「够短」
步骤输入输出负责
① HashToPoint盐 r（40 字节）‖ 消息 m多项式 c（n 个系数，每个 mod q）把消息变成一个「随机」目标多项式；用 SHAKE256，是唯一的哈希步骤
② Decompress签名里的压缩串 s多项式 s₂，或「解码失败 → 拒绝」把变长编码还原成系数
③ 多项式乘法c、s₂、公钥 hs₁ = c − s₂·h mod q格算术；q = 12289，n = 512（NIST Level I，最低一档安全等级）
④ 范数检查s₁、s₂接受 / 拒绝接受当且仅当 ‖(s₁, s₂)‖² ≤ ⌊β²⌋，即两者「够短」

关键对比：Falcon 的公钥 pk = h 就是一个多项式。ML-DSA 的公钥是种子 ρ 加 t₁，验签要先用 SHAKE128 从 ρ 展开整个矩阵 Â（ExpandA），还要算 tr = H(pk)（公钥的哈希）。

每一步内部怎么算

来源：Falcon round-3 规范 v1.2，Alg. 16（Verify）和 Alg. 3（HashToPoint）。falcon.pdf

  1. c ← HashToPoint(r‖m)：SHAKE-256 吸收 40 字节盐 r 和消息，然后每次挤出 16 bit 得到 t。只有 t < 5q = 61445 才收下，c_i = t mod q，凑满 n 个系数为止。（k = ⌊216/q⌋ = 5，拒绝采样是为了让 c_i 均匀。）
  2. s₂ ← Decompress(s)：签名里的 s₂ 是变长编码（Golomb-Rice 风格，一种对小整数很省空间的编码），解码失败直接拒绝。
  3. s₁ ← c − s₂·h mod q：一次多项式乘法。
  4. s₁ 先规约到 [−q/2, q/2]，然后算整数平方和，不开根号。

3. 藏公钥时，Keccak 次数差多少

场景
持有人不想暴露是哪个发证方签的（公钥本身会成为追踪标识），于是把公钥从 statement（公开）挪到 witness（秘密）
后果
原来 verifier 在电路外做的「公钥相关计算」，现在必须搬进电路里证明
ML-DSA
要搬进电路：ExpandA（ρ → Â）+ tr = H(pk) → 多出约 106 次 Keccak
Falcon
公钥 h 直接作为 witness 承诺，没有展开、没有额外哈希 → 多出 0 次
公钥公开公钥隐藏多出来的部分
ML-DSA-44≈ 10≈ 116ExpandA：16 个多项式 × ≤ 6 个 SHAKE128 块 ≈ 96；tr：1312 B 公钥 ÷ 136 B rate ≈ 10
Falcon-512≈ 9≈ 9无：h 直接作为 witness 承诺，不需要展开
Falcon 的 ≈ 9 是怎么算出来的

要 512 个系数，每个 2 字节，接受率 61445/65536 ≈ 0.94，所以平均需要约 1092 字节输出。SHAKE-256 的 rate（每次置换能挤出的字节数）是 136 字节，1092 ÷ 136 ≈ 8.03，再加上吸收那一下，约 9 次置换。每次 Keccak-f[1600] ≈ 38,400 个 AND 门，所以 Falcon 约 0.35M AND（M = 百万），ML-DSA 藏公钥时约 4.5M AND。

诚实的边界（他们一定会追问，主动说也行）：
  • 这是只数 Keccak的估算，不是电路实测。Falcon 也有它自己的贵处：Decompress 是变长编码，放进电路不便宜；平方范数要对 1024 个系数做整数平方加和。
  • HashToPoint 的拒绝采样次数取决于数据，电路要按上限布置，或者让 prover 提供接受位置再验证（类似他们在 SampleInBall 里用 prover 提供 index 的做法，见第 0006 课）。
  • 数字按 round-3 规范算；FIPS 206（FN-DSA = FFT over NTRU-Lattice-Based Digital Signature Algorithm，NIST 标准化中的 Falcon）还是草案，定稿时细节可能变。
  • FLOCK 输出的是「与 Falcon 兼容」的签名。讲的时候用这个词，不要说「FIPS 206 签名」。

4. 一个值得想的点：Decompress 要不要进电路

想法
不在电路里跑 Decompress，直接把解码后的 s₂ 当 witness
电路输入
公开：c（或 r‖m）；秘密：s₂（以及藏公钥时的 h）
电路证明
「存在短向量 (s₁, s₂) 满足 s₁ + s₂h = c」
好处
省掉一个变长解码电路
状态
只是一个想法，没有证明

直觉：这正是 Falcon 不可伪造性所依赖的困难问题，安全性似乎没丢。但没有证明（比如编码长度上限带来的差别）。面谈里把它说成 "one question I'd want to work out"，不要说成结论。

域的选择（可以问 Matteo 的问题）

q − 1 = 12288 = 3·212，所以 𝔽q 里有 1024 次单位根，512 点 negacyclic NTT（模 Xⁿ + 1 的多项式乘法所用的 NTT = Number Theoretic Transform 数论变换）可以直接做。他们为 ML-DSA 用的是 𝔽q 的 6 次扩张（Fp24_6，为了 sumcheck 的 soundness 可靠性）；Falcon 大概也要类似的扩张。这是一个可以问 Matteo 的问题。

5. 60 秒口头版本

To make the credential post-quantum, the issuer only has to swap ECDSA for a lattice signature; the proof system is already hash-based. For ML-DSA your circuit already exists, so the next step is putting it into the full mdoc statement and measuring end to end. Falcon is the more interesting one: its public key is a single polynomial, so hiding the key costs essentially nothing extra in hashing. By my count that's about nine Keccak permutations, against roughly a hundred and sixteen for ML-DSA with a hidden key. That's only the hashing, of course. Decompress and the norm check have their own cost, and FIPS 206 isn't final yet. But I think it's worth measuring.

自测

Q1. 为什么 Falcon 藏公钥几乎不多花 Keccak？
ML-DSA 的公钥是种子 ρ，要用 ExpandA 展开矩阵 Â（约 96 次置换）；Falcon 的 h 直接作为 witness。
Q2. HashToPoint 里一个 16-bit 样本 t 什么时候被收下？
k = ⌊2^16/q⌋ = 5，t < kq 时收下并取 t mod q，保证均匀。
Q3. 让 mdoc 后量子，持有人侧要改的是什么？
证明系统已经只依赖哈希；只有电路里检查发证方签名的那一块要换成 ML-DSA 或 Falcon 验签。
